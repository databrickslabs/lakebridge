## Prerequisites

### 1. Authentication

The profiler signs in with a **Programmatic Access Token (PAT)** or a **key pair**:

- **PAT**: see [Snowflake: Programmatic access tokens](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens#generating-a-programmatic-access-token). PATs need a [network policy](https://docs.snowflake.com/en/user-guide/network-policies) on the user.
- **Key pair**: see [Snowflake: Key-pair authentication](https://docs.snowflake.com/en/user-guide/key-pair-auth). The public key must be registered on the user.

### 2. Required Permissions

The role needs read access to `SNOWFLAKE.ACCOUNT_USAGE`, for example `ACCOUNTADMIN` or a role granted:

```sql
GRANT IMPORTED PRIVILEGES ON DATABASE SNOWFLAKE TO ROLE <role>;
```

The `rate_sheet` step also reads `SNOWFLAKE.ORGANIZATION_USAGE.RATE_SHEET_DAILY`. If the account isn't ORGADMIN-enabled, or is billed through a reseller, the view returns no rows and the rest of the profile still completes. If the role can't read the view, the step fails; skip it with `--exclude rate_sheet`.

### 3. Network Access

The machine running the profiler needs access to Snowflake, including the cloud storage that large query results are downloaded from. Allow the hosts listed by `SELECT SYSTEM$ALLOWLIST();`.

## Configure Connection to Snowflake

```bash
databricks labs lakebridge configure-database-profiler
```

Pick **snowflake**, choose **PAT** or **Key-Pair**, and enter your account URL, user, and PAT or private key path. The warehouse, database, schema and role prompts have defaults.

## Execute the Profiler

```bash
databricks labs lakebridge execute-database-profiler --source-tech snowflake
```

The profiler will:
1. Connect to Snowflake using the configured credentials
2. Extract the last 90 days of `SNOWFLAKE.ACCOUNT_USAGE` data
3. Store the results in a local DuckDB extract file

`query_history` excludes SQL text. `query_samples` holds a random sample of 10,000 queries with their text.
