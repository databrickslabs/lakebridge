# Legacy SQL DW Profiler Details

- [Prerequisites](#prerequisites)
- [Profiled Tables and Views](#profiled-tables-and-views)
- [Configure Connection to Legacy SQL DW](#configure-connection-to-legacy-sql-dw)
- [Execute the Profiler](#execute-the-profiler)

:::info
"Legacy SQL DW" refers to **Azure SQL Data Warehouse** and **Azure Synapse Analytics dedicated SQL pool** —
MPP-based platforms that expose Parallel Data Warehouse (PDW) Dynamic Management Views (`sys.dm_pdw_*`).
For serverless SQL pools, Spark pools, and the Synapse workspace control plane, use the
[Synapse profiler](./synapse) instead.
:::

## Prerequisites

### 1. Download
- ODBC driver for SQL Server (https://learn.microsoft.com/en-us/sql/connect/odbc/download-odbc-driver-for-sql-server?view=sql-server-ver18)
- (Windows only) Visual C++ (https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170)

### 2. SQL Server Authentication

:::warning Attention:
Multi-factor Authentication (MFA) is **not** supported. The Legacy SQL DW profiler connects via ODBC, which does not support MFA.
You must use **SQL Authentication** (username and password) to connect to the dedicated SQL pool.
:::

### 3. Required Database Permissions

The SQL user configured for the profiler must have read access to the system catalog views and PDW Dynamic Management Views
listed in [Profiled Tables and Views](#profiled-tables-and-views).

:::warning Attention:
`VIEW SERVER STATE` is **not supported** on a dedicated SQL pool. You must use `VIEW DATABASE STATE` instead,
which is granted **per database**.
:::

Connect to the target dedicated SQL pool as an admin and run:

```sql
-- Create a contained user from the server login
CREATE USER [<user_name>] FROM LOGIN [<user_name>];

-- Grant access to PDW Dynamic Management Views (sys.dm_pdw_*)
GRANT VIEW DATABASE STATE TO [<user_name>];

-- Grant access to object definitions (routines, views)
GRANT VIEW DEFINITION TO [<user_name>];

-- Grant read access to INFORMATION_SCHEMA views
GRANT SELECT ON SCHEMA::INFORMATION_SCHEMA TO [<user_name>];
```

:::tip
The profiler queries server-level catalog views such as `sys.database_service_objectives` and `sys.databases` from
the target database context. `VIEW DATABASE STATE` covers the `sys.dm_pdw_*` DMVs used to extract sessions,
requests, and per-node storage statistics.
:::

## Configure Connection to Legacy SQL DW

Run the following command to configure the profiler connection to your dedicated SQL pool:

```console
databricks labs lakebridge configure-database-profiler

Please select the source system you want to configure
[0] synapse
[1] mssql
[2] legacy sql dw
Enter a number between 0 and 2: 2

(local | env)
local means values are read as plain text
env means values are read from environment variables, and fall back to plain text if not variable is not found

Enter secret vault type (local | env)
[0] env
[1] local
Enter a number between 0 and 1: 1
Enter the fully-qualified server name: my-dw-server.database.windows.net
Enter the port details: 1433
Enter the SQL username: profiler_user
Enter the SQL password:
Enter the ODBC driver installed locally (default: ODBC Driver 18 for SQL Server):
```

### Configuration Parameters

| Parameter | Description | Default |
|:----------|:------------|:--------|
| **Secret vault type** | `local` for plain text values, `env` to read from environment variables | — |
| **Server name** | Fully-qualified hostname of the dedicated SQL pool | — |
| **Port** | Server port number | — |
| **SQL username** | SQL Authentication username | — |
| **SQL password** | SQL Authentication password (hidden input) | — |
| **ODBC driver** | Locally installed ODBC driver name | `ODBC Driver 18 for SQL Server` |

:::info
Legacy SQL DW pins `fetch_size = 1000`, `login_timeout = 30s`, and `tz_info = UTC` — these are not prompted at configure time.
Adjust them by editing the generated credentials file directly if needed.
:::

## Execute the Profiler

Once configured, run the profiler to extract metadata and activity metrics from your dedicated SQL pool:

```bash
databricks labs lakebridge execute-database-profiler --source-tech "legacy sql dw"
```

The profiler will:
1. Connect to your dedicated SQL pool using the configured credentials
2. Execute the schema metadata and activity metric extraction queries
3. Store the results in a local DuckDB extract file

### Publish Profiler Summary Dashboard

After executing the profiler, you can upload the results and deploy a summary dashboard to your Databricks workspace:

```bash
databricks labs lakebridge create-profiler-dashboard \
  --extract-file /tmp/data/legacy_sqldw_assessment/profiler_extract.db \
  --source-tech "legacy sql dw" \
  --volume-path /Volumes/lakebridge_profiler/profiler_runs \
  --catalog-name lakebridge_profiler \
  --schema-name profiler_runs
```

Refer to the [Profiler Guide](../#publish-profiler-summary-dashboard) for full details on dashboard deployment options.
