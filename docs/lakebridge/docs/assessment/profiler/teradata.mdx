## Prerequisites

### 1. Teradata connectivity and driver

- Network access to the Teradata system.
- No driver install required for the Teradata profiler.
- Access to the Teradata database with appropriate permissions.

### 2. Required permissions on system views

Grant `SELECT` access to:

- `DBC.DBCInfoTbl`
- `DBC.ResUsageSpma`
- `DBC.DiskSpaceV`
- `DBC.TablesV`
- `DBC.FunctionsV`
- `DBC.ColumnsV`

### 3. Optional PDCR access for longer-history analysis

When available, the profiler also extracts Teradata PDCR tables for richer, aggregated history (up to 180 days). To enable this, grant `SELECT` access to:

- `PDCRINFO.DBQlogTbl_Hst`
- `PDCRINFO.DBQLSummaryTbl_Hst`
- `PDCRINFO.UserInfo`

<Admonition type="info" title="PDCR is optional">
PDCR access is not required. The profiler always runs the core `DBC`/DBQL extraction and additionally attempts the PDCR extraction; if `PDCRINFO` is not present or not accessible, the PDCR steps are skipped automatically and the run still succeeds. See [Workload Extraction](#workload-extraction).
</Admonition>

```console
databricks labs lakebridge configure-database-profiler

[0] bigquery

[4] redshift
[5] snowflake
[6] synapse
[7] teradata
Enter a number between 0 and 7: 7

(local | env)
local means values are read as plain text
env means values are read from environment variables fall back to plain text if not variable is not found

Enter secret vault type (local | env)
[0] env
[1] local
Enter a number between 0 and 1: 1
Enter the Teradata server or host details: td-host.example.com
Enter the user details: dbc_user
Enter the password details:
Enter the default database name (default: DBC):
```

The generated credential block (written to `~/.databricks/labs/lakebridge/.credentials.yml`) includes:

- `teradata.host`
- `teradata.user`
- `teradata.password`
- `teradata.database`

## Run the Profiler

There is no variant to choose — a single run performs both the core and PDCR extraction (see [Workload Extraction](#workload-extraction)). Optionally verify connectivity first:

```console
databricks labs lakebridge test-profiler-connection --source-tech teradata
```

Then run the extraction:

```console
databricks labs lakebridge execute-database-profiler --source-tech teradata --output-folder /path/to/output
```

`--output-folder` is optional; if omitted you are prompted for it (defaulting to
`~/.databricks/labs/lakebridge_profilers/<source-tech>_assessment`).

This executes the extraction steps defined in the Teradata pipeline configuration and produces a local
DuckDB extract in the output folder, named:

```
profiler_extract_<source-tech>_<version>_<YYYYMMDD>.db
```

The extract contains the system, storage, object, user-database, UDF, and workload tables gathered from the source.

## Workload Extraction

There is no variant to select. A single profiler run extracts the system, storage, object, user-database, and UDF
tables, plus workload data from two sources when they are available:

| Workload source | Steps | Availability |
|---|---|---|
| Core `DBC` / DBQL tables | `td_dbql_core_info_extract` | Always runs; requires only the system-view grants above. |
| PDCR aggregated history (`PDCRINFO`) | `td_pdcr_info_agg_extract`, `td_pdcr_sp_exe_info_agg_extract` | Runs when PDCR is accessible; provides richer, longer-history workload aggregates. |

The PDCR steps are optional: if `PDCRINFO` is not present or not accessible (for example `Error 3802 ... Database
'PDCRINFO' does not exist`), those steps are skipped automatically and the run still succeeds with the core DBQL
workload data. The core workload data is typically narrower (recent days from DBQL rather than long historical
aggregates), which can reduce long-horizon trend analysis and may underrepresent short-query aggregate metrics — so
granting PDCR access is recommended where possible.

## SQL Text Redaction

The Teradata profiler does **not** export raw SQL query text. In the DBQL-core extract the `SQLTextInfo`
column is redacted to a fixed `[REDACTED]` value at extraction time, so query text never leaves the source
system. Workload analysis relies on statement classification and performance metrics rather than the raw SQL.

## International Character Support

Lakebridge preserves multilingual metadata (for example Japanese, Korean, and Thai text) in Teradata profiler extracts.

- The `teradatasql` driver runs the session over UTF-8 and returns character data as already-decoded text,
  so international characters are preserved end to end with no lossy client-side re-encoding.
